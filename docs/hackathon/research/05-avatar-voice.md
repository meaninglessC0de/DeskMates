## 1. Summary (10 lines)

1. **Use Synthesia for the live face** (it is a bounty inside our own track, 50,000 credits). It renders a lip-synced avatar into a LiveKit room; we keep our own STT, LLM and TTS. `verified`
2. **Hard constraint:** only Synthesia *synthetic* and *personal* avatars work for interactive sessions. Stock actor avatars (Ryan, Ada) do not, on any plan. `verified`
3. **No custom face from an arbitrary image.** Personal avatars need a live consent video of the person in the photo, so a generated portrait cannot be used. Synthetic avatars are picked in the Synthesia web app, not generated by our app. `verified`
4. **Same face in sidebar and call:** pick the roster of synthetic avatars once, and use each avatar's own still as the portrait (screenshot or one captured frame). No avatar-list or thumbnail API was found. `verified` (absence in docs) / `unverified` (capture trick)
5. **Voice is bring-your-own TTS** in the API path (Synthesia says Synthesia voices are not available through it; another Synthesia page claims a built-in option, so they conflict). Plan on ElevenLabs, Cartesia or Deepgram TTS. `verified` / conflicting
6. **Cost is tiny:** 10 credits per avatar minute ($0.10). 50,000 credits is 5,000 minutes (83 hours). A launch page also advertises 500 free minutes. `verified`
7. **Needs a Python LiveKit Agents worker** running on the user's Mac (outbound connection to LiveKit Cloud) plus a free LiveKit Cloud project. Node plugin exists on npm (1.10.0, published 2026-11-13) but Synthesia's own skill and LiveKit's docs still say Python only. Use Python. `verified`
8. **Access is the top risk:** docs conflict on whether a key needs Enterprise or a free key (500 free minutes). Freemium concurrency is 1 session, paid plans 100. Ask the Synthesia sponsor on arrival. `verified` (conflict)
9. **Group meeting:** build a *staged* meeting. One Synthesia session with up to 5 avatar IDs and `swap_avatar()` shows the active speaker live, others as stills; a router in our app picks speakers. One concurrency slot, one session of credits. Real simultaneous avatars need a paid-plan concurrency and are not recommended. `verified` (API) / `unverified` (swap latency)
10. **Fallback ladder:** Synthesia live face, then Anam free tier (3-minute calls, same face possible), then audio-only call with the still and a speaking ring, then a pre-recorded call clip. Build the audio-only call first; the avatar is a 3-line addition.

## 3. Q1: Synthesia Interactive Avatar API end to end

### Auth and keys
- Create a key in the Synthesia web app: Developers, API keys, New API key, grant scopes (the interactive endpoints need `interactive_avatars:write`; a `:write` scope also covers `:read`), choose expiry (7 days to never, default 30 days). The key is shown once. `verified` https://docs.synthesia.io/docs/developers.md, https://docs.synthesia.io/reference/createinteractiveavatar
- Header: `Authorization: Bearer <key>` (bare key also works). API base `https://developers.synthesia.io`. `verified`
- Keys belong to the user account, not the workspace. `verified` https://docs.synthesia.io/reference/synthesia-api-quickstart
- Keep it server-side: it is a workspace secret and must never reach the browser. `verified` (quickstart README)

### Objects and endpoints
- `POST /api/interactive-avatars/avatars` body `{sourceId: "av_...", regenerate?: bool}`: converts a Studio avatar into an interactive avatar, async (`queued, processing, completed, failed, canceled`; poll by repeating the same request; a drained balance returns 402 on any poll). Duration is not documented. The plugin README says: copy the ID from the Avatars page `•••` menu, convert, poll until `completed`, use the returned `id`. `verified` https://docs.synthesia.io/reference/createinteractiveavatar, https://docs.synthesia.io/reference/ia-livekit-plugin-reference
- `POST /api/interactive-avatars/sessions` body `{avatarIds[1+], livekitUrl (wss), livekitToken}`. Returns 201 `{id: "ses_...", status: "active", createdAt}`. Deadline 75 s. `verified` https://docs.synthesia.io/reference/createinteractiveavatarsession
- Errors use RFC 9457 problem details, branch on `code`: `feature_not_in_plan` 402, `no_credit` 402, `quota_exceeded` 402, `concurrency_limit` 429, `rate_limited` 429, `conflict` 409 (room closed or avatar participant removed), `validation_error` 400 (media connection to LiveKit could not be established: "WebRTC ports (UDP/TCP) or a TURN server must be reachable; HTTP-only tunnels don't carry media"), `service_unavailable` 503, `timeout` 504. `verified` https://docs.synthesia.io/reference/errors
- No session list, transcript, recording, or webhook system exists. Capture transcripts with our own STT. `verified` https://docs.synthesia.io/reference/ia-operational-trust

### The LiveKit room model (who does what)
- **We** own the LiveKit room (LiveKit Cloud project), the user's client, the agent worker, and mint all tokens. There is no Synthesia session token. `verified` https://docs.synthesia.io/reference/ia-concepts
- Plugin path: our agent worker connects to the room first, then `AvatarSession.start()` mints a room token for the avatar worker inside our process (using our LiveKit key and secret and the agent's identity), calls `POST .../sessions`, and Synthesia's hosted worker joins the room as participant `synthesia-avatar-agent` (default; identity must be unique per concurrent avatar, a duplicate evicts the first). `start()` returns once the avatar has joined and published video (default wait 30 s, quickstart uses 60 s). `verified` plugin reference + `avatar.py` in wheel 1.8.12 (`ATTRIBUTE_PUBLISH_ON_BEHALF`, `perform_rpc` for swap)
- Direct REST path: we mint the avatar's token and call `/sessions` ourselves. Same result, more plumbing; no reason to use it. `verified`
- Audio path: our agent's TTS audio is intercepted (`session.output.audio` is replaced) and sent to the avatar worker over a LiveKit data stream (`DataStreamAudioOutput`); the worker publishes lip-synced video and audio as normal tracks. Never reassign `session.output.audio` afterwards; attach **before** `session.start()`. `verified`
- The user's client is a plain LiveKit client: subscribe to the avatar's tracks and attach both to **one** `<video>` element so they share a MediaStream. Tokens need `sync_streams=True` for A/V sync, and explicit agent dispatch via `RoomAgentDispatch(agent_name=...)`. `verified` (`minimal/server.py`, `minimal/index.html`)
- Video quality is set by the worker; on the client use `adaptiveStream: false` or `setVideoQuality(HIGH)` if blurry. `verified` (skills reference)

### Plugin vs REST, and Python vs Node
- Python: `livekit-plugins-synthesia` 1.8.12 on PyPI, needs `livekit-agents` 1.8.2+, Python 3.10-3.14. `verified` (PyPI JSON)
- Node: `@livekit/agents-plugin-synthesia` 1.10.0 on npm (versions from 1.9.1 on 2026-10-09 to 1.10.0 on 2026-11-13), peer deps `@livekit/agents` 1.10.0 and `@livekit/rtc-node` ^1.2.2. The tarball README shows `new synthesia.AvatarSession(new synthesia.AvatarConfig({avatarIds}))` and `swapAvatar()`. Synthesia's plugin reference documents it too. `verified`
- Conflict: Synthesia's skill ("Node.js agents are not supported"), its marketing page ("Only Python LiveKit Agents are supported") and LiveKit's plugin page ("Python only") predate the Node plugin. Treat the Node plugin as brand new and untested by us. `verified` (conflict)
- **Recommendation: Python worker**, the path every quickstart and the skill exercise. The user's Mac has `uv`, Python 3.11.4 and Node 26 (checked locally; not installed anything). `lk` (LiveKit CLI) is not installed; it is optional (`brew install livekit-cli` is what the quickstart uses; the dashboard also gives keys).
- A 15-minute Node spike is allowed only if the build team wants one language; do not make it the plan.

### Audio in, voices out
- STT, LLM and TTS are all ours. Synthesia: "TTS is bring-your-own, so Synthesia voices aren't available through this API. Match your TTS voice to the avatar's persona." `verified` https://docs.synthesia.io/reference/ia-overview
- Conflict: Synthesia's launch update says a Synthesia-hosted TTS is available through the plugin "at no extra cost" and the launch post says Synthesia-hosted TTS exists as an add-on. The plugin source (wheel 1.8.12, 7 Python files) has no TTS code path. Assume BYO. `verified` (conflict)
- Match voice to avatar gender and age, or it "reads as broken" (skill). `verified`

### Bring your own LLM
- Two ways in LiveKit Agents (Python), both documented: (a) override `Agent.llm_node(chat_ctx, tools, model_settings)` and yield text (plain `str`, `ChatChunk`, or `FlushSentinel()` to push text to TTS immediately); (b) use the OpenAI plugin pointed at our own OpenAI-compatible server by overriding base URL and key. `verified` https://docs.livekit.io/agents/build/nodes/, https://docs.livekit.io/agents/models/ (OpenAI-compatible providers via base URL)
- The worker runs on the user's Mac (it connects out to LiveKit Cloud), so it can call `http://127.0.0.1:<port>` of our app. The quickstart runs `python agent.py dev` locally against Cloud. `verified`
- See section 7 (recommended architecture).

### Events, errors, latency
- Plugin events: Python `session_ended` and `error` (avatar stopped publishing); Node exposes neither (watch the room for the avatar participant leaving). No reconnect after a drop: call `start()` again. `verified`
- `SynthesiaError.type`: `AUTH, FEATURE_NOT_IN_PLAN, UNKNOWN_AVATAR, QUOTA_EXCEEDED, INVALID_ROOM_TOKEN, LIVEKIT_CREDENTIALS_REJECTED, INVALID_SESSION_REQUEST, RATE_LIMITED, CONCURRENCY_LIMIT, TIMEOUT, CONNECTION`, with `retryable` and `retry_after`. `verified`
- Latency is **not published**; the vendor FAQ says it is "still working to improve latency". The minimal quickstart claims a 0.3-0.5 s saving per turn from a preflight hack (OpenAI Realtime), which does not apply to our LLM. Cold start (avatar joining) can take noticeably longer than a normal turn. `verified` / `unverified` numbers. My estimate for a turn is in section 5.

## 4. Q2: Avatar identity in Synthesia

- **Stock roster for the Video API:** a table of ~614 rows (`EXPRESS-1` 17, Version 3 525, Version 2 34, Version 1 38 by one count), with Avatar_ID but **no thumbnail or preview field**, and no list endpoint described; ID is obtained by `Copy ID` in the app. `verified` https://developers.synthesia.io/docs/avatars (count mine, may be off). These are video-API stock avatars; most are actor-based and **cannot** be interactive. `verified`
- **Interactive-compatible:** "Only synthetic and personal avatars." Synthetic = fully AI-generated avatars not based on a real person (in the stock library, customizable outfits and backgrounds). `verified` https://docs.synthesia.io/reference/ia-operational-trust, https://help.synthesia.io/en/articles/6341418-avatars
- How many synthetic avatars exist, and which are interactive-ready: not documented. One launch page says the API supports "Express 2 avatars, including synthetic and cartoon avatars"; another says Express-3 Style Avatars can be made interactive. `verified` (conflict) Must be looked at in the Synthesia Avatars page once a workspace is available. Expect a few dozen at most (`unverified`).
- **IDs are inconsistent in the docs:** `createinteractiveavatar` wants a Studio `av_...` ID and returns an interactive ID; the plugin accepts `av_...` IDs; the quickstart says copy the **Interactive ID** from the `•••` menu (a UUID such as Jenny `8788bef1-8020-46e0-a8f4-510ea9989b25`). The skill's older default (Kenji, `7572faa9-15da-400d-8227-ef1ab8932523`) may be stale. Test with whatever the workspace UI offers. `verified` (inconsistency)
- **Custom avatars:**
  - Personal avatar from photo: one photo (jpg/png, one person, waist-up, landscape) plus a **live consent video of the same person**; typically ready within minutes; paid plans only. A generated portrait cannot satisfy consent. `verified` https://docs.synthesia.io/docs/personal-avatars.md
  - Avatar Builder (Style avatars, Express-3): created in the web app from a preset and a text prompt, a reference image is "soon"; each option costs 14 credits; takes 2-3 minutes; API creation and interactive use are not described on that page, though the launch post says Style Avatars can be made interactive via the API. `verified` https://docs.synthesia.io/docs/avatar-builder.md, https://www.synthesia.io/post/synthesia-launches-new-ai-assistant-for-faster-video-creation-and-express-3-avatar-model (reported summary via search)
  - Studio avatars: $1,000/year add-on, green-screen footage. Not relevant. `verified`
- **Voices:** none from Synthesia in the API path (section 3). Pair each avatar with a TTS voice of matching gender and age.
- **Can the sidebar portrait be the avatar's own preview?** Yes in principle, but there is no API field. Three ways, cheapest first: (1) save the avatar's thumbnail from the Synthesia Avatars page by hand (6 screenshots); (2) capture one frame from the avatar's video track during setup (canvas `drawImage` of the `<video>` while idle; a 15-second session is about 2.5 credits); (3) generate a short pre-rendered video via the legacy video API and take its thumbnail (the docs list JPG and GIF thumbnail endpoints for videos). Option 2 gives exact pixel match with the call; option 1 is zero-risk. `unverified` (capture not tried)
- **"Hiring" in this design:** the persona generator picks an avatar from a pre-curated roster of 6-10 interactive-ready synthetic avatars (match gender, age, role), and fills name, personality, voice and system prompt. It does not generate a new face. That is a product consequence to flag to the orchestrator.

## 5. Q3: Alternatives (brief)

### Anam (anam.ai), the best same-face option
- **Custom avatar from one image:** `POST` create-avatar with `displayName` and `imageUrl` or an uploaded file, or via the Lab UI. Sources may be a real photo, a stock photo, or an AI-generated image with compatible facial features; moderation and compatibility checks apply. Input: png/jpg/webp, at most 4.5 MB, square, at least 1152x1152, head and shoulders with margin, neutral, mouth closed, plain background. Unlimited saved avatars on every plan including Free; daily generation limits apply (no number given). The pricing page says under 2 minutes to generate. `verified` https://anam.ai/docs/personas/avatars/custom-avatars.md, https://anam.ai/docs/personas/avatars/custom-avatar-best-practices.md, https://anam.ai/pricing
- **Stills:** `GET /v1/avatars/{id}` returns `imageUrl` (still preview) and `videoUrl` (idle loop). So the portrait and the call face match by construction. `verified` https://anam.ai/docs/personas/avatars/gallery.md
- **Bring your own LLM:** (a) server-side: register an endpoint (OpenAI, Azure, Gemini or Groq format, must stream SSE), Anam's servers call it, so a local app needs a public URL; (b) client-side: set `llmId: "CUSTOMER_CLIENT_V1"` in the session token, listen for `MESSAGE_HISTORY_UPDATED`, call our endpoint ourselves, and push text with `createTalkMessageStream()` / `talk()`; Anam does STT and TTS itself (`voiceId` in the session config). Client-side works against a local endpoint. `verified` https://anam.ai/docs/personas/llms/custom-llms.md, https://anam.ai/docs/javascript-sdk/examples/custom-llm.md
- **Own TTS audio:** `enableAudioPassthrough` plus `sendAudioChunk()` (pcm_s16le, mono, 24 kHz ideal); 480 ms start-up buffer per sequence; `interruptPersona()`. `verified` https://anam.ai/docs/javascript-sdk/examples/custom-tts.md
- **SDK:** `@anam-ai/js-sdk`; session token via `POST https://api.anam.ai/v1/auth/session-token` (key stays server-side), `createClient(token)`, `streamToVideoElement(id)`. Also a LiveKit plugin for Node (`@livekit/agents-plugin-anam` 1.10.0) and Python (`livekit-plugins-anam` 1.8.12). `verified` (docs + registries)
- **Tools:** client tools, webhook tools, system tools. `verified` (docs index)
- **Plans:** Free $0, 30 min/month, 1 session, **3 min max per call**; Starter $12, 50 min, 1 session, 5 min; Explorer $49, 250 min, 3 sessions, 10 min; Growth $299, 2,000 min, 5 sessions, 2 h. Silence does not pause billing. `verified` https://anam.ai/pricing, https://anam.ai/docs/personas/session/duration.md, https://anam.ai/docs/resources/billing-and-limits.md
- **Latency:** no figures published. `verified` (absence)
- **Verdict:** best technical fit for "face from our own image", simplest stack (JS only, no Python, no LiveKit in our path). Free tier is enough only for short demo calls. Prize is in the other track.

### ElevenLabs
- **Agents platform:** four parts (ASR, LLM or custom LLM, low-latency TTS, turn-taking model); 10,000+ voices; SDKs React, Swift, Kotlin, React Native, Unity; WebSocket protocol. `verified` https://elevenlabs.io/docs/eleven-agents/overview
- **Custom LLM:** OpenAI-compatible `/v1/chat/completions` or `/v1/responses`, SSE streaming required, must support function calling for system tools, cannot be used with their Realtime models, and a local server needs a public URL (ngrok). `verified` https://elevenlabs.io/docs/agents-platform/customization/llm/custom-llm
- **Avatars:** ElevenLabs' own Avatars make **pre-rendered** talking-head videos, no API yet ("planned"). Real-time faces come from partners: HeyGen LiveAvatar (documented), Anam, Lemon Slice (reported). `verified` https://elevenlabs.io/docs/overview/capabilities/image-video/avatars, https://elevenlabs.io/docs/eleven-agents/guides/integrations/live-avatar.md
- **Price and free tier (official pricing page):** Agents Speech Engine $0.08/min; TTS $0.04-0.08 per 1k chars depending on model; Scribe v3 STT $0.20/hour, realtime $0.22/hour. Free plan: 10,000 credits per month (about 10 minutes of TTS), 2 concurrent requests, 3 custom voice slots; commercial license from Starter ($6/month after $1 first month); free tier needs attribution (reported). `verified` https://elevenlabs.io/pricing/api, https://elevenlabs.io/pricing
- **Use for us:** voices via the LiveKit ElevenLabs plugin (`livekit-plugins-elevenlabs` 1.8.12, `@livekit/agents-plugin-elevenlabs` 1.10.0 exist). Whether LiveKit Inference serves ElevenLabs is not stated, so use the direct plugin and our own key. `verified` (registries)

### fal
- **Portraits:** official prices: FLUX.1 schnell $0.003/MP; FLUX 2 $0.012/MP; FLUX 2 Flash $0.005/MP; Nano Banana $0.0398/image; Nano Banana 2 $0.08/image; Seedream V4.5 $0.04/image. A 1-megapixel portrait is about $0.003-0.04. No free credits mentioned on the page. `verified` https://fal.ai/pricing

- **LiveKit Agents defaults** in the Synthesia minimal quickstart: Cartesia Ink-2 STT and Sonic-3.6 TTS through LiveKit Inference (billed to LiveKit credit, no separate key), Silero VAD, `turn_detection="stt"`, preemptive generation on, interruption `min_duration=0.75 s`. `verified` (`minimal/agent.py`)
- Voice per employee: store `{tts_provider, voice_id}` on the persona; for ElevenLabs the free plan has 3 custom voice slots, otherwise pick library voices. Match gender and age to the avatar.
- **Routing the LLM step to our agent:** run a tiny **OpenAI-compatible streaming endpoint inside our app** (`POST /v1/chat/completions`, SSE, `model` field = employee id). In the worker: `openai.LLM(base_url="http://127.0.0.1:PORT/v1", api_key="local", model=<employee_id>)`, or an `llm_node` override that streams from our endpoint and yields text (add `FlushSentinel()` after the first sentence to cut time to first audio). The endpoint ignores the posted history if it keeps its own, builds the "call mode" prompt (current task summary, last screenshot or its caption, persona), calls Claude with streaming, and streams text back. Spoken replies must be short (one to three sentences, no markdown); our endpoint, not the worker, enforces that. `verified` (mechanisms) / `unverified` (our endpoint)
- **Turn handling:** push-to-talk gives the most reliable demo (manual mode is documented: set `turn_detection="manual"`, disable audio input, `commit_user_turn()` on release); keep VAD as an option toggle. A hackathon hall is noisy; Quail Voice Focus noise isolation exists but adds a LiveKit charge. `verified`
- **Expected end-to-end latency** (my estimate, `unverified`, to be measured): end-of-turn 0.3-0.7 s + STT final 0.1-0.3 s + our LLM first sentence 0.7-1.8 s (Claude streaming with vision is the dominant term) + TTS first audio 0.15-0.4 s + avatar render and transport 0.3-1.0 s = about **1.6-4 s** from end of speech to a moving mouth. To reduce: fast model for calls, cached context, ask for first sentence only before tools, `preemptive_generation`, a filler phrase when the brain is slow ("One sec"), and speak immediately from a pre-computed task summary instead of calling tools mid-call.

### Q5: Group call design

**Feasibility**
- Several Synthesia avatars in one room are supported by the plugin if each has a unique `avatar_participant_identity` (docs: "Use unique values to run multiple avatars in one room"). Each is its own session and counts against concurrency: Freemium 1, paid 100. Credits scale linearly (3 avatars = 30 credits/min). `verified`
- Several agents in one room means several dispatched worker jobs, each with its own STT stream hearing the user, so they would all answer at once without a coordinator. `unverified` (inferred from LiveKit's dispatch model)
- LiveKit Build allows 5 concurrent agent sessions and 100 participants. `verified`

**The cheaper alternative: one session, swapping the avatar**
- `AvatarConfig(avatar_ids=[up to 5])` precomputes five avatars; `await avatar.swap_avatar(id)` switches the rendered avatar mid-session (default timeout 15 s; latency not published); all swappable IDs must be listed at start. One session, one concurrency slot, one set of credits. `verified` plugin reference + `avatar.py`
- **Design:** one agent job per meeting, one `AgentSession` and one Synthesia session with the attendee avatar IDs. Our app runs a **router**: it receives the user's transcript, decides who answers and returns a sequence of `{speaker_id, text}` segments. Per segment the worker does `swap_avatar(avatar_id)` (only when the speaker changes), switches the TTS voice (ElevenLabs and Cartesia expose option updates; otherwise a `tts_node` override), yields the text, and publishes `{type:"speaker", id}` on a data topic so the Astryx UI highlights that tile and shows subtitles. Non-speaking attendees are Astryx tiles with their stills. `unverified` (voice switching and swap latency must be tested)
- **Turn-taking rules (simplest that works):** push-to-talk for the human; the router picks the speaker by name mention first, else by role relevance (one LLM call, deterministic fallback = first attendee); at most two employee replies per human turn; an employee may name another ("Maya, can you cover the design part?") and the router lets that employee answer next; no employee-to-employee chatter unless the user asks for a discussion, then cap at 4 turns. No hand-raising needed.
- **Cost:** one session = 10 credits/min regardless of attendees; 2-5 attendees fit. `verified` (pricing) 
- **Recommendation: build the staged meeting** (router plus `swap_avatar`), after the one-to-one call is solid. If `swap_avatar` is slow or fails in testing, degrade to "speaker's still lights up with the voice playing, avatar tile stays on the last speaker" (audio-only meeting with subtitles). Do **not** attempt simultaneous live avatars: it needs paid concurrency, N workers and a hard coordination problem for little demo value. This honours decision D-013 (drop group if too complex).

## 11. Recommended architecture

### Components (processes, languages, packages)
1. **Electron main (TypeScript)**: owns personas, the "brain" HTTP server, token minting, and spawns the voice worker. Package `livekit-server-sdk@^2.19` (Node) for tokens and agent dispatch.
2. **Brain endpoint (in Electron main, localhost)**: `POST /v1/chat/completions` (OpenAI-compatible, SSE), `model` = employee id. Calls our Claude-based employee agent with call-mode prompt, current task, last desktop screenshot; streams text. Also `POST /meeting/turn` (router) returning NDJSON `{speaker, text}` for the staged meeting. Same endpoint serves the Anam fallback client-side pattern.
3. **Voice worker (Python 3.10-3.14, run with `uv`)**: `livekit-agents[silero,deepgram,elevenlabs,openai]~=1.8` (latest 1.8.12), `livekit-plugins-synthesia~=1.8` (1.8.12), `python-dotenv`. One file based on `minimal/agent.py`: `AgentSession(stt=deepgram.STT(model="nova-3"), llm=openai.LLM(base_url=BRAIN_URL, model=employee_id, api_key="local"), tts=elevenlabs.TTS(voice_id=...) or deepgram.TTS(...), vad=silero)`, then `AvatarSession(AvatarConfig(avatar_ids=[...]), join_timeout=60)`, `await avatar.start(session, room=ctx.room)` **before** `session.start(...)`; retry on `retryable` errors. `agent_name` set, explicit dispatch with job metadata carrying `{employee_id, avatar_ids, voice, brain_url}`. `session.on("user_input_transcribed")` and `conversation_item_added` publish transcripts to the UI over a data topic. Started by Electron as a child process (`uv run agent.py start`), pre-warmed at app launch so calls start fast.
4. **Renderer (React + Astryx)**: `livekit-client@^2.24` only. Call screen: Astryx layout with the avatar `<video>` (tracks of the avatar participant attached to one element), the live desktop view, mute/push-to-talk and end buttons; "Calling..." state; audio-only state shows the still with a ring.
5. **LiveKit Cloud (free Build project)** and **Synthesia hosted avatar worker** (not ours).

### Call sequence: "user clicks Call" to "avatar speaks"
1. Renderer asks main to start a call with employee X; shows the "Calling" state.
2. Main creates a unique room name, mints a user token (identity `user`, `room_join`, `RoomConfiguration(sync_streams=True, agents=[RoomAgentDispatch(agent_name="employee-call", metadata=JSON(persona))])`) and returns `{url, token}`.
3. Renderer `room.connect(url, token)`, enables the mic (or push-to-talk), subscribes to tracks.
4. LiveKit Cloud dispatches the job to the already-running worker; the worker connects to the room.
5. Worker `AvatarSession.start()` mints the avatar token, calls Synthesia `POST /api/interactive-avatars/sessions`; Synthesia's worker joins as `synthesia-avatar-agent` and publishes video (several seconds, up to the join timeout).
6. Worker starts `AgentSession`, then `generate_reply` greets: the LLM call goes to the brain endpoint, text streams to TTS, audio goes to the avatar over the data stream, lip-synced video and audio return to the room.
7. Renderer receives `TrackSubscribed`, attaches both tracks, switches the call screen from "Calling" to live; transcript lines arrive on the data topic.
8. User speaks (push-to-talk or VAD): STT, brain endpoint (employee agent with task and screenshot), TTS, avatar. Barge-in: LiveKit interruption handling.
9. End: renderer disconnects, the job closes, the avatar leaves; credits stop. If step 5 times out: drop to audio-only (rung 2) and show a notice.

### Data each side needs
- **Persona record (stored by our app):** `id, name, role, personality, system_prompt, avatar_interactive_id, portrait_path, tts_provider, voice_id`.
- **Worker:** persona metadata via dispatch, `BRAIN_URL`, all provider keys in env.
- **Brain:** employee id, conversation, current task state, latest screenshot, call mode flag.
- **Renderer:** LiveKit URL and token only. No provider keys in the renderer.

### Keys and accounts the user must provide
1. **Synthesia** workspace with an API key that has Interactive Avatar access (`interactive_avatars:write` scope) and, in the app, 6-10 interactive-ready synthetic avatars chosen and their Interactive IDs copied; the sponsor can add credits.
2. **LiveKit Cloud** free project (URL, API key, secret).
3. **Deepgram** key (free $200 credit) for STT and dev TTS.
4. **ElevenLabs** key (free plan) for demo voices, optional.
5. **Anthropic** key for the employee brain (already planned).
6. Optional: **Anam** free key for rung 1 (self-serve, no card).
Not needed: fal, OpenAI (the minimal quickstart uses OpenAI Realtime; we replace it with our brain endpoint).

### Build order for the overnight plan
1. Audio-only call (LiveKit room, worker, STT, brain endpoint, TTS, ring UI). 2. Add the three avatar lines and the auto-fallback. 3. Portrait capture for the roster. 4. Staged meeting (router, swap, UI highlight). 5. Optional Anam adapter.

## 13. Risks and unknowns

1. **Synthesia access and concurrency** (`unverified` for our key): conflicting docs, 1 concurrent session on Freemium. Mitigation: ask sponsor; fallback rungs 1-2.
2. **Avatar roster is unknown and cannot be generated by our app.** Fewer than 6 usable faces would hurt "hire from role". Mitigation: pick faces on arrival; allow two employees to share a face only as a last resort.
3. **Interactive ID confusion** (`av_` vs UUID): test the first avatar before designing flows.
4. **Latency** of the full loop is unmeasured; Claude with screenshots may exceed 2 s to first token. Mitigation: call-mode prompt, small model, cached context, filler phrase.
5. **Cold start** of the avatar can take tens of seconds (60 s join timeout in the quickstart). Mitigation: "Calling" screen, auto audio-only fallback.
6. **Python worker packaging** inside an Electron Mac app (uv, venv, process supervision, `dev` mode reload vs `start`). Mitigation: run from `uv` at app start, health check, restart.
7. **Group meeting:** `swap_avatar` speed and per-speaker voice switching are unproven; fallback is the audio-only meeting.
8. **Free-tier ceilings:** ElevenLabs 10k credits (about 10 min), LiveKit $2.50 inference credit if we use LiveKit Inference. Mitigation: Deepgram for dev, ElevenLabs only for the demo.
9. **Venue network:** WebRTC UDP, noisy mic. Mitigation: hotspot, headset, push-to-talk.
10. **Cross-track bounty rule unknown** (not found publicly).
11. **Node plugin** is days old and conflicts with vendor docs; do not depend on it.
12. **macOS microphone permission and entitlement** for the packaged Electron app (`unverified` details).
13. **Anam fallback legal/quality:** using a Synthesia still as the Anam source image is untested and its terms are unchecked.
14. The Synthesia `x-deadline-seconds: 75` on both endpoints is unexplained; treat avatar creation time as unknown.
