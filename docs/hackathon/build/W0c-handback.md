## Store (`api/store.ts`, zustand, `useStore`)
Data (`Data` in `api/reducer.ts`): `bootState` ('idle'|'loading'|'ready'|'error'), `bootError`, `connected`, `employees` (always sorted needs_you, stuck, then `lastActivityMs` desc), `threads[employeeId]` = `{messages, steps, approvals, task, typing, loaded, loading, error, hasMore}` (the current task and approvals live in the thread slice; there is no separate `tasks` map), `presets`, `settings`, `capabilities`, `team[range]`, `teamRange`, `teamLoading`, `teamError`, `teamConversationId`, `call` (null when no call; `{id, info, employeeIds, state, mode, participants, speaker, captions, captionSeq, hands}`), `toast` (`{seq,text,tone}`; `ToastBridge` in App shows it with Astryx `useToast`), `ui` = `{view:'thread'|'team', selectedId, hireOpen, profileOpen, settingsOpen, summonOpen, desktopOpen: Record<employeeId, boolean>}`.

Actions (one per API route; all call `api/client.ts`): `boot`, `refresh`, `startRealtime` (WebSocket, returns stop; refetches on reconnect), `applyServerEvent`, `setData`; ui: `setUi(patch)`, `setView`, `toggleDesktop(id, open?)`, `showToast`; employees: `selectEmployee` (clears unread, marks read, loads thread), `fetchCandidate`, `hire` (closes the dialog and selects), `patchEmployee`, `removeEmployee`, `pauseEmployee`, `resumeEmployee`, `setControl(id,on)`, `desktopAction(id, 'restart'|'reset'|'start'|'stop')`, `openStream(id, req)`, `grantScreen(id, minutes)`, `revokeScreen`; thread: `loadThread`, `loadOlder`, `sendMessage`, `markRead`, `decideApproval(id, req)`; calls: `startCall(ids)`, `addressCall(employeeId)`, `endCall`; team/settings: `loadTeam(range?)`, `askTeam(req)`, `updateSettings(patch)`.
Error rule: `fetchCandidate`, `hire`, `askTeam` rethrow `ApiClientError` (`.code`, `.message`) so the dialog shows its own message (`team_full`, `genie_off`); every other action shows a toast and returns null/false. Selectors: `selectSelected`, `selectLive`, `needsAttention` (Dock badge count).
Events: `reduceEvent` (pure, `api/reducer.ts`) handles every `ServerEvent` type; side effects are `markRead` and `window.shell?.notify` (the latter only when the window is not focused on that thread). Unread is server-authoritative (`employee` events); the client only clears it locally on select or when a message arrives in the open thread. Call events may arrive before `POST /api/calls` returns: the store creates a placeholder call (`id: null`) first and adopts the first event's call id. `ended` sets `call` to null; `failed` keeps it so the Stage can show the failure and `endCall()` closes it.

## Shots
Add a state: append `{ name, query? }` to that area's `shots.ts` (plain data, no imports; the script imports it with Node). Page is `/?shot=<area>/<name>&<query>`. `fixtures/load.ts` documents the parameters, all optional: `employees=none`, `select=maya|priya|jonas|ines`, `boot=loading|error`, `thread=loading|error|empty`, `open=hire,profile,settings,desktop,summon`, `view=team`, `range=today|week|month`, `team=loading|error`, `call=one|meeting`, `callState=connecting|live|failed`, `callMode=audio|avatar`, `caps=nollm,nohost,genie,databricks,calls_off,calls_avatar,cua`. Area defaults: `hire/*` opens the hire dialog, `profile/*` the drawer, `settings/*` settings, `desktop/*` the panel, `team/*` the team view, `stage/*` a live call. Any other parameter is readable with `useShot()?.params` (`fixtures/shot.ts`). In shot mode `api/client.ts` answers every route from the fixtures (`fixtures/fakeApi.ts`: candidates cycle through the unhired cast, hire returns a new employee, messages echo), so dialogs can be exercised. `loadThread`/`loadTeam` do not overwrite fixture state a shot asked for (loading, error).
`npm run shots [-- <area>] [-- --web <url>]`: starts its own Vite server on a free port, warm-up visit, then light and dark at 1280x800 scale 2, waits for fonts and network idle, intercepts `/media/portraits/*` and `frame|thumbnail.jpg` with placeholder SVGs, fails on console errors, page errors or the text "Something went wrong". Output `shots/<area>/<name>-{light,dark}.png`. Fixtures are in `fixtures/data.ts` (four seeded people, a thread each with messages, steps, an approval and a task with a plan; 8 presets and candidates; team reports for all ranges; settings; capabilities).

## Deviations and notes
- `initApp()` lives in `App.tsx` but is called from `main.tsx` (loading the store during `App`'s render would update a subscribed parent).
- `Data.bootState`, not `boot` (it would clash with the `boot()` action).
- Electron: `sandbox: false` because electron-vite emits the preload as `index.mjs` (ES module); `package.json` has no `"main"`, so launch with `out/main/index.js` (the smoke script does). `AGENT_MANAGER_SHOT=<area>/<name>` is a small test hook in `src/main/index.ts` (file:// build opens that fixture state); W9 may keep or drop it.
- electron-vite's renderer build is not minified (2.4 MB main chunk); `vite.web.config.ts` build is 881 kB.
- No `ws` or `fetch` is attempted on `file://` (ws guard in `connectWs`).
- Not verified: against a running office (not started, per brief); the real `<Theme mode>` switch for `appearance: 'dark'|'light'` from settings (only `system` with emulated colour scheme was screenshotted); keyboard shortcuts, toasts and the `window.shell` bridge are not built.
- Vite proxy errors (`ECONNREFUSED 127.0.0.1:4317`) in the Vite log are expected when running `npm run web` without office.
- Processes: nothing of mine is left running (the other `vite` processes in `pgrep` belong to other projects).
