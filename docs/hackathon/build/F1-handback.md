## Per issue
**I-2 flicker.** Cause: `closeTask` refreshed (idle) before `setStuck` ran, and `postEmployee` patched the employee (still `working`) before the task closed (`supervisor.ts` `reportStuck`, `finishTask`, `closeTask`). Change: `patch()` can be held and announced once (`batch()`); `closeTask` writes `activeMs` itself (no extra task event); stuck is set before the close (`failTask`, `closeAfterTurn`, `flushClose`); `resume()` and `sendMessage` no longer pass through `idle` on the way out of stuck. Tests: `runtime.integration.test.ts` "report_stuck goes from working straight to stuck", "finish_task: the done bubble, then the closed task ... idle together". Real (S8): `message stuck` 01:37:59.042, then `task failed cost 0.0023`, `employee Jonas stuck` in the same millisecond 01:38:00.853-.854; no idle between. Real (S10, finish): `message done` 01:41:27.166, `task done cost 0.00076` and `employee Maya idle` both at 01:41:28.135.

**I-3 missing activity line.** Cause: `addStep` compared the unclipped sentence with a 60 s window, across tasks and closed steps. Change: coalesce only when the previous step has the same task, same (clipped) sentence, and is still running, or ended under 2 s ago in the same turn. Tests: "a new command in a new task is a new running step", "the same action twice in a row inside one task is one step". Real (S10): `step running "Ran a command"` at 01:38:13.231 in a brand-new task right after an earlier command.

**I-6 greeting before idle.** Cause: `startRuntime(..., markUp)` set the desktop up and refreshed to `idle` before the hire turn. Change: `greeting` flag; `compute()` keeps `starting / Starting desktop` until the greeting turn ends (30 s safety timer, also cleared on dispose); manager and colleague items arriving meanwhile (including ones held while the desktop starts) wait in `greetHeld` and are delivered when it ends, as a normal turn; `turnStarted` does not mark them seen during the greeting. Tests: "stays starting until the greeting turn ends, and a message sent meanwhile is a normal task after it", "is idle only after the greeting bubble". Real (S1): greeting bubble 01:37:36.823, `idle` 01:37:37.841. This also explains the rare flake of "delivers the briefing ..." (it read `inputs[0]` at the early idle); it passed 4 of 4 runs now.

**I-9 cost.** Cause: `finish_task`/`report_stuck` run before the turn result, which carries the cost. Change: inside a turn the bubble is posted at once and the task close (with idle or stuck) is held until `turnEnded` brings the cost, at most 3 s; outside a turn it closes at once. Chat-only and greeting turns were already written to `usage` with a null task but `/api/team` only summed tasks: added optional `TeamData.usageWithoutTask` (store implements it) and `computeTeamReport` adds it to rows and totals. Test: "plain chat turns and the greeting add their cost to the team totals". Real: the closed task events above carry the real cost. Not done: the Databricks warehouse report (`REPORT_SQL`) still sums tasks only, so with Databricks on, chat spend is missing there.

**I-1 duplicate bubble.** Cause (reading, confirmed by test): the runtime already skips the trailing text when a tool spoke in the same turn. The duplicate comes across turns: she ends a turn with plain text (task open), the supervisor nudges, and the nudge turn calls `ask_user`/`finish_task`/`report_stuck` with the same sentence. Change: `RuntimeHost.messageUser(text, { final: true })` (claudeRuntime passes it for the trailing text); with a task open the supervisor holds that text (20 s timer) and drops it if the next tool bubble says substantially the same thing (`sameSaying`: containment or word overlap 0.4), otherwise posts it first. Tests: "ends a turn with ask_user: the sentence is posted once", "keeps her plain text when the nudge turn says something different". Not covered: she calls `message_user` and then `finish_task` with the same sentence (seen once in S10); that is the prompt's job (F2).

**I-7 second half.** `inbox.ts` already held the permission notice while idle (passive item). It was still sent on its own while a turn ran (busy rule). Now a permission notice never releases anything alone; it rides with the next real message or nudge. The screen-grant notices still steer mid-turn. Tests: `inbox.test.ts` "keeps a permission notice back even while a turn is running", integration "a permission change is not a turn of its own". `briefing.ts` unchanged.

## For the renderer
- Order change: the employee event now comes before the message event it belongs to (unread count), and `task` (closed, with cost) and `employee` (idle or stuck) come after the done or stuck bubble, together, up to 3 s later.
- A new hire stays `starting / Starting desktop` until the greeting is written, so `idle` now arrives after the first bubble (about 1 s later), not 3 to 4 s before it.
- A message typed during that window is stored and shown at once, shown as seen only after the greeting, and answered as a normal task.
- A closed task's cost is final in the event that closes it; chat-only spend is only in `/api/team`, never on a task.
